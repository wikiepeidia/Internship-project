## Established Terminology (with citations)

The judge's mental model (encoder + softmax head, or "additional layers added to QLoRA for tightening classification") describes exactly **one** recognized family of approaches. This project uses a second, equally recognized, differently-named family. Both have names in the literature; neither is "not real classification."

**1. Text-to-text classification / classification-as-generation.**
The foundational framing: cast every NLP task, including classification, as conditional text generation, where the model emits the literal label string (e.g. `"positive"`, `"bank_impersonation"`) as generated tokens rather than a probability vector over a fixed output layer.
Source: Raffel, C., Shazeer, N., Roberts, A., et al. (2020). "Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer" (T5). *Journal of Machine Learning Research*, 21(140), 1–67. — canonical origin of this framing; T5 was trained so that, e.g., SST-2 sentiment labels are generated as literal tokens ("positive"/"negative") rather than predicted through a classification head.

**2. Verbalizer.**
The technical term for the mapping between a model's generated natural-language token(s) and the underlying fixed label set. This is the standard vocabulary a thesis should use to name the mechanism by which a generative model's free-text output collapses onto a closed 4-class label space.
Sources: Schick, T. & Schütze, H. (2021). "Exploiting Cloze Questions for Few-Shot Text Classification and Natural Language Inference" (PET). *EACL 2021* — introduces the verbalizer concept formally. Canonicalized in the widely-cited survey: Liu, P., Yuan, W., Fu, J., Jiang, Z., Hayashi, H., & Neubig, G. (2023). "Pre-train, Prompt, and Predict: A Systematic Survey of Prompting Methods in Natural Language Processing." *ACM Computing Surveys*, 55(9), 1–35.

**3. Instruction-based classification, contrasted directly with "embedding-based / classification-head" classification.**
This is the single most directly useful citation for the thesis, because it names and empirically compares the *exact two architectures* the judge was asking about, on the same causal-LLM base model, and treats both as legitimate:
Yousefiramandi, A. & Cooney, C. (2025). "Fine-Tuning Causal LLMs for Text Classification: Embedding-Based vs. Instruction-Based Approaches." arXiv:2512.12677. The paper explicitly names:

- **"Classification Head on LLM Embeddings"** (= what the judge expected): attach a lightweight classifier on top of the causal LLM's final hidden state, using the LLM as a frozen/fine-tuned encoder.
- **"Instruction-Tuning for Classification"**: convert each training example into a prompt and the label into a target text response, "effectively turning the classification task into a text generation task conditioned on an instructional context" — i.e., exactly this thesis's approach (JSON-structured label output via QLoRA-tuned next-token prediction).

**4. LLM-as-Classifier (generation-based, single/few-token decoding).**
"LLM as a Classifier: Leveraging Large Language Models for Text and Vision Classification" (OpenReview, 2025, forum ID 78WdKlYSeO) names the family "LaaC" and formalizes classification-via-constrained-generation as a legitimate, competitive paradigm (a fine-tuned Gemma-3-27B under this framing outperformed GPT-4o/GPT-5 on MIntRec 2.0 while running an order of magnitude faster).

**5. Structured generation / schema-constrained generation for classification.**
The applied/deployment-facing term for what this thesis's system actually does: a JSON schema is used as the generation target, and the label is one field among several (alongside evidence spans and recommendations) inside that schema. This is a recognized production pattern for LLM classification, not a workaround; see general structured-output literature, e.g. Cai, R. et al., "SLOT: Structuring the Output of Large Language Models" (arXiv:2505.04016), and standard "structured outputs" documentation from major LLM providers describing exactly this pattern (fixed enum field extracted from a constrained-generation JSON response).

**Bottom line for the thesis:** the correct umbrella terms to use are **"generative classification"** or **"instruction-based (text-generation) classification with a verbalizer,"** explicitly contrasted with the judge's expected **"embedding-based classification-head"** approach. Both are named, studied paradigms; this project deliberately chose the former.

## Precedent Examples (2-3 real citable works)

**1. Yousefiramandi & Cooney (2025), arXiv:2512.12677** (cited above). Directly precedent-setting: fine-tunes the *same* causal decoder-only LLM two ways — attaching a classification head vs. instruction-tuning it to generate the label as text — and reports the tradeoffs of each (head: higher F1, more calibrated, fewer trainable params, faster; instruction-based: more flexible, integrates naturally with free-text generation, more sensitive to prompt/output formatting). Establishes that the instruction-based/generative route is a real, published, deliberately-chosen alternative, not a workaround.

**2. Lin, Z., Liu, Z., & Fan, H. (2025). "Improving Phishing Email Detection Performance of Small Large Language Models." arXiv:2505.00034.** Directly analogous in domain (phishing detection) and scale (~3B-parameter decoder LLMs, runnable on consumer-grade GPUs — the same class of constraint as this thesis's 4B model on 8GB VRAM). The authors fine-tune a small generative LLM using what they name **"Explanation Augmented Fine-tuning"**: the model is trained to emit both the phishing/legitimate label *and* an explanation as generated text in the same pass, explicitly to reduce hallucination and improve interpretability — no classification head is used. This is close to a direct precedent for this thesis's label+evidence+recommendation JSON output.

**3. "A Culturally Aware LLM Framework for Analyzing Social Engineering Tactics in Korean Phishing Messages." *Electronics*, 15(10), 2196 (2026). DOI: 10.3390/electronics15102196.** Architecturally the closest precedent found: an LLM-based framework that outputs a **multidimensional structured codebook per phishing message** — including the phishing label, tactic type, relation type, requested action, cultural lever, **and evidence span** — moving explicitly "beyond simple binary phishing detection" toward "structured and explainable analysis." This is functionally the same output shape as this thesis's system (risk tier + threat class + grounded evidence span + recommendations), applied to a different non-English, culturally-localized phishing domain (Korean vs. Vietnamese). Strong citation for "localized, non-English, evidence-grounded generative phishing classification is an active, precedented research direction," directly rebutting any implication that this design is idiosyncratic or non-standard.

**4. (Supporting/foundational, not domain-matched) Narang, S., Raffel, C., et al. (2020). "WT5?! Training Text-to-Text Models to Explain Their Predictions." arXiv:2004.14546.** The foundational precedent for *jointly* generating a label and its explanation in one text-to-text pass, with no separate classification head or separate explanation module. Empirically, WT5 shows joint label+explanation generation produces a *stronger label–explanation correlation* (more faithful) than a two-stage pipeline that predicts first and explains second, or that uses two separate mechanisms. This is the strongest available academic backing for the specific design choice of generating `risk_tier` + `threat class` + `evidence spans` + `recommendations` together in one QLoRA-tuned forward pass rather than splitting label prediction (head) from explanation generation (a second mechanism).

## Argument For This Architecture (unified structured output rationale)

Use this structure in the new subsection — state the alternative fairly, then give the specific, sourced reasons this project chose generative structured-output classification instead:

1. **What a classification-head architecture would have required.** Bolting a linear/MLP classification head onto the LoRA-adapted decoder's final hidden state (Yousefiramandi & Cooney's "embedding-based" approach) would produce *only* a label. It has no native mechanism for the other three required output fields — grounded evidence spans quoted from the input, and safety recommendations. Producing those would require either (a) a second, separate generation-capable model/head bolted alongside the classifier, or (b) a second inference call to the base LLM for explanation after the head made its decision. Either way, the "add a classification head" suggestion trades one simplification (a slightly better-calibrated label) for a second, decoupled explanation mechanism — exactly the pipeline structure WT5 (Narang et al., 2020) shows is *less faithful* than joint generation, because the label and its justification are no longer produced from a shared, consistent generation context.

2. **Faithfulness/grounding argument (WT5 precedent).** WT5's empirical result — joint label+explanation generation correlates more strongly (is more faithful) than explain-then-predict or predict-then-explain pipelines — is directly applicable here: this system's evidence spans are generated in the *same* forward pass as the label, conditioned on the same hidden state that produced the label, rather than retrofitted by a separate module after the fact. This is a defensible, citable reason the evidence spans are trustworthy/grounded, not just a side effect of using an LLM.

3. **The verbalizer *is* the classification mechanism — QLoRA does not need "additional layers" to do classification.** The judge's exact phrase was needing "additional layers added to QLoRA for tightening for classification." The correct rebuttal, sourced from the terminology above: QLoRA is a parameter-efficient *fine-tuning* method for the existing decoder stack — it adapts attention/projection weights, it is not itself a classification mechanism and was never meant to be one. The classification signal is supplied entirely through the **training objective**: next-token cross-entropy loss computed over the label tokens inside the JSON target (the `label`/`risk_tier` field). The fixed vocabulary of literal class strings (`bank_impersonation`, `zalo_social_engineering`, `task_scam`, `benign`) the model is trained to reproduce in that field **is the verbalizer** (Schick & Schütze, 2021) — the standard, named mechanism by which a generative model's output space collapses onto a closed label set. No extra parameters are structurally required for this to be genuine classification; it is realized through training-time supervision on the generation target, exactly as in Yousefiramandi & Cooney's "instruction-tuning for classification" and as in T5's original text-to-text label generation.

4. **Practical/deployment argument (project-specific, defensible without overclaiming).** This project's own hard constraint is local, offline, consumer-laptop inference within an 8GB VRAM budget (single 4B decoder-only backbone, GGUF-quantized). A classification-head-plus-separate-explanation-module design would mean maintaining and running two mechanisms (or two calls) instead of one; the single-forward-pass, single-model, unified JSON generation design directly serves the resource constraint that motivated using one parameter-efficiently fine-tuned decoder model in the first place. This is a legitimate engineering rationale, not just an academic one, and should be stated as such — a deployment tradeoff, not a claim that generative classification is unconditionally superior to head-based classification.

5. **Honest framing — do not overclaim.** Yousefiramandi & Cooney's direct comparison also shows the classification-head route can win on raw calibration, F1, and inference speed in some settings. The thesis should state plainly: a classification head is a legitimate, often stronger choice *when the only required output is a single label*; this project chose the generative/instruction-based route specifically *because* the task additionally required grounded evidence spans and free-text recommendations to be produced in a way that stays consistent with the predicted label — a requirement a bare classification head does not address, and that a second bolted-on mechanism would only address at the cost of an extra, less-faithful pipeline stage.
