# Phase 41.1 Plan 03: Neutral Integrity, Artifact, and Runtime Ownership Summary

Strict phase-neutral artifact boundaries, secret-free runtime settings, and disjoint dependency extras remove historical training/provider ownership from the installed runtime graph without changing frozen CLI or serialization contracts.

## Accomplishments

- Added strict UTF-8/duplicate-key JSON reads, canonical JSON bytes, bounded descendant validation, SHA-256 helpers, exclusive writes, and no-overwrite atomic publication under the phase-neutral `src.core` boundary.
- Added active manifest, registry, release-evaluation, and model-artifact contracts in `src.artifacts`; frozen historical schemas/training implementations retain their baseline identities and import no active module.
- Routed local-model lookup, GGUF/accelerated registry reads, and runtime-doctor release reads through neutral artifacts, closing the installed runtime's transitive `src.model_adaptation` dependency.
- Split provider, data, modeling, and runtime settings ownership while preserving every legacy `Settings` field/default/env-file precedence and keeping `get_settings()` intentionally uncached.
- Reduced base installation metadata to Pydantic, pydantic-settings, and ftfy; moved generation, corpus/NLP, training, evaluation, and local model runtime packages into exact reviewed extras without installing anything.
