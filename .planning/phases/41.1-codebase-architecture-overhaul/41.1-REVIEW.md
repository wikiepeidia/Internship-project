# Phase 41.1: Code Review Report

**Reviewed:** 2026-08-27T03:49:48Z  
**Depth:** standard

## Summary

The refactor has substantial correctness, security, and data-integrity defects and is not safe to ship. The most severe findings let recovery ingest finalized test rows, split a single seed across train/validation/test, accept self-authored reporting evidence, execute code from an unverified model path, report invalid release artifacts as passing, and bypass the held-out deny-open guard with keyword arguments. Several tests actively codify the unsafe behavior or check only duplicated declarations, so a green architecture suite would provide false confidence.

This was a source-only review. No reserved split, `data/splits` directory, ProgramData evidence, D-drive model root, model loader, training/evaluation/inference flow, provider, or historical producer-closure content was accessed or executed. The migration catalog does defer execution correctly and rejects unknown IDs before import; the remaining migration issue is classified as a warning below.

## Narrative Findings (AI reviewer)

### Critical Issues

#### CR-01: Recovery directly admits finalized train, validation, and test splits

**Classification:** BLOCKER  
**File:** `src/data_pipeline/workflows.py:223-242` (consumed at `src/data_pipeline/workflows.py:338-365`)  
**Issue:** `_recoverable_record_paths()` recursively walks the entire configured data root and explicitly accepts `train.jsonl`, `val.jsonl`, and `test.jsonl`. `optimize_recovered_records()` then loads those rows into recovered training outputs and produces new splits. Running the advertised recovery command can therefore leak held-out rows into training and traverse redirected content below the broad root.  
**Fix:** Replace the recursive name-based search with a closed allowlist of generation/checkpoint staging roots; categorically reject every finalized split tree and reparse escape. Decode strict UTF-8 and fail/quarantine label conflicts instead of first-wins recovery. Add a synthetic test proving all finalized split paths are excluded without probing live data.

#### CR-02: Salvage overwrites the primary corpus after silently discarding input

**Classification:** BLOCKER  
**File:** `src/data_pipeline/workflows.py:144-181`  
**Issue:** `salvage_partial_records()` skips malformed JSON, does not validate rows as `DatasetRecord`, silently keeps the first same-text record even when labels conflict, and replaces `generated.jsonl` with the reduced result. If both inputs are absent it creates an empty primary artifact. A repair command can therefore destroy valid data while reporting success.  
**Fix:** Require at least one nonempty source; validate every line and collect malformed/conflict errors before any write; fail closed on conflicting labels; publish a fully validated staged file only after success, retaining a recovery receipt or backup of the previous artifact.

#### CR-03: “Group-safe” splitting puts one seed in all three partitions

**Classification:** BLOCKER  
**Files:** `src/data_pipeline/core/splits.py:121-180`; `tests/architecture/test_data_core_contract.py:234-260`  
**Issue:** Labels with fewer seed groups than active splits are deliberately moved to record-level allocation. Records sharing one `seed_id` can then be distributed across train, validation, and test. The architecture test explicitly expects six records from `seed-shared` to become 4/1/1, codifying contamination while calling the behavior grouped splitting.  
**Fix:** Treat each seed group as indivisible for every label. If label diversity cannot populate every split, either leave support empty and report it or fail closed; never split a seed to meet target counts. Assert that each seed ID appears in at most one output split.

#### CR-04: Small or negative recovery targets expand to the maximum corpus

**Classification:** BLOCKER  
**Files:** `src/data_pipeline/workflows.py:297-312`; `src/data_pipeline/cli.py:20-24`  
**Issue:** For `target_count <= 3`, including negative values, `requested` becomes zero and `selected_per_class` is set to the full feasible count. A request for zero records can therefore emit the largest balanced corpus instead of zero, and the CLI accepts these values without validation.  
**Fix:** Reject negative/unsupported target counts at the parser and public API boundaries. Define zero explicitly as an empty result, and allocate non-divisible positive remainders without exceeding the requested total.

#### CR-05: Resume and cleanup can delete unrelated or last-known-good files

**Classification:** BLOCKER  
**Files:** `src/data_pipeline/workflows.py:529-531,564-577`; `src/data_pipeline/cli.py:82-87`  
**Issue:** A caller controls `checkpoint_dir`; after processing, the workflow deletes every matching `checkpoint-*.jsonl` in that directory. Resume also unlinks an existing completed `generated.jsonl` before seeds are loaded or generation succeeds. A bad checkpoint path or later exception can delete unrelated checkpoints or the only good corpus.  
**Fix:** Canonicalize and bound checkpoint directories below an owned per-run root, record the exact files created by that run, stage resumed output separately, and purge/replace only those owned files after the new output passes full validation. Add a failing-generator test that proves the previous completed artifact remains byte-identical.

#### CR-06: Dataset manifests can escape their root and ignore declared counts

**Classification:** BLOCKER  
**Files:** `src/data_pipeline/core/records.py:116-136`; `src/data_pipeline/core/splits.py:215-240`  
**Issue:** Manifest keys and SHA/count/byte fields are unvalidated. `verify_manifest()` joins arbitrary absolute or `..` keys to `data_dir`, follows them, hashes the resulting external file, and compares only SHA-256; it ignores declared byte and record counts. `save_manifest()` also truncates the destination non-atomically. This can validate the wrong files and corrupt a previously valid manifest on interruption.  
**Fix:** Require normalized relative no-reparse descendants and strict lowercase SHA/nonnegative count/size fields. Verify hash, byte size, strict-UTF-8 row count, and exact membership. Publish through a staged exclusive/atomic writer with an explicit replacement policy.

#### CR-07: Unverified registry paths reach `trust_remote_code=True`

**Classification:** BLOCKER  
**Files:** `src/artifacts.py:117-149,323-353`; `src/runtime/analyzers/local_model.py:714-722`; `src/runtime/analyzers/accelerated.py:37-55,72-109`; `src/runtime/analyzers/gguf.py:45-71`  
**Issue:** Registry and download-manifest `local_path` values may be arbitrary relative, absolute, or reparse paths. Registry SHA-256 is only length-checked and neither analyzer verifies it before loading. The accelerated analyzer passes the resulting base-model path to Hugging Face with `trust_remote_code=True`, enabling Python execution from an attacker-controlled local model directory. The GGUF path is likewise loaded without hash or root verification. Tests bless arbitrary temp paths and fake hashes (`tests/architecture/test_integrity_artifacts.py:65-85,191-219`; `tests/architecture/test_runtime_boundaries.py:119-132`).  
**Fix:** Require fixed absolute protected artifact roots, no-reparse bounded descendants, exact candidate/schema metadata, and a byte/tree hash verified immediately before load. Set `trust_remote_code=False`; if custom model code is unavoidable, vendor and hash-allowlist every code file separately.

#### CR-08: Held-out readiness is derived from caller-supplied prose

**Classification:** BLOCKER  
**File:** `src/artifacts.py:170-210`  
**Issue:** `HeldOutSupportAudit` sets `ready=True` and `verdict=PASS` solely when the caller leaves `blocker_reasons` empty. All-zero support passes, and the supposedly locked label/risky-label tuples are caller-overridable. The type therefore does not enforce its “fail-closed” contract.  
**Fix:** Require the exact locked tuples/order, derive blockers from required support/risky-label rules, reconcile the evaluated path/root, and reject any caller-supplied status or reason set inconsistent with computed facts. Add an all-zero-support/empty-reasons rejection test.

#### CR-09: Release artifacts accept impossible `PASS` states

**Classification:** BLOCKER  
**Files:** `src/artifacts.py:265-299`; `tests/architecture/test_runtime_boundaries.py:320-347`  
**Issue:** `ReleaseEvaluationArtifact` accepts `PASS` with no per-label metrics, zero evaluated rows, below-floor risky recalls, blocker reasons, explanation blockers, or a `BLOCK` readiness audit. The validator skips order enforcement when metrics are empty. The runtime architecture test constructs a one-row `PASS` with no label metrics/readiness audit and asserts the doctor accepts it, actively endorsing the fail-open contract.  
**Fix:** Require exactly one ordered metric row per locked label, reconcile support totals and evaluated rows, enforce recall floors and readiness, and compute or validate the verdict from all blocker/flag sources. Reverse the runtime test to reject incomplete or contradictory artifacts.

#### CR-10: The default registry writer fails after mutating the filesystem

**Classification:** BLOCKER  
**Files:** `src/config/settings.py:58-59`; `src/artifacts.py:366-379`; `src/core/integrity.py:92-133`  
**Issue:** The default registry path is relative, while `atomic_replace_new_artifact()` requires a canonical absolute path. Default `pilot --dry-run` persistence therefore fails. `save_model_registry()` calls `mkdir(parents=True)` before validation, so a rejected unbounded/redirecting path can still create directories. Existing tests use only absolute `tmp_path` destinations.  
**Fix:** Resolve the configured registry below a trusted absolute artifact root, validate containment and ancestry before any filesystem mutation, and then create only the validated parent. Test the real default and rejected `..`/reparse cases for zero side effects.

#### CR-11: Integrity primitives have path-swap and cleanup races

**Classification:** BLOCKER  
**File:** `src/core/integrity.py:27-37,92-155,158-195`  
**Issue:** `sha256_file()` follows links despite promising a regular file. The writers lstat ancestry, then later open/link/hash by path; a writable ancestor can be swapped to a junction between those operations. On failure, cleanup unlinks `target`/temporary by path after another actor can replace it, potentially deleting someone else’s file. The “never lose races” test (`tests/architecture/test_integrity_artifacts.py:162-188`) covers only a target collision before publication, not ancestor or post-publication replacement.  
**Fix:** Use no-follow directory/file handles and descriptor-relative or Win32 handle-based operations, fstat and revalidate stable identities, bind operations to a protected root, and unlink only when the current file identity matches the object this call created.

#### CR-12: Archive publication and verification trust redirecting destinations

**Classification:** BLOCKER  
**Files:** `scripts/archive_phase41_source_closure.py:409-489,511-539`; `tests/architecture/test_provenance_boundary.py:250-260`  
**Issue:** Source ancestry is checked, but archive destination ancestry is not. `_write_exclusive()` follows reparse parents. Verification uses `rglob('*')` plus `is_file()`, which follows metadata and ignores unexpected root entries, empty directories, and some link/reparse members. A redirected or non-exact archive can therefore be published or verified. The test adds only one regular file under `tree`, missing these cases.  
**Fix:** Validate the fixed destination and each component through stable no-follow handles; enforce exact membership at both archive root and tree levels; reject every unexpected file, directory, link, and reparse point; add redirected-parent and non-file-member tests.

#### CR-13: Reporting authority is self-signed instead of pinned to the frozen evidence

**Classification:** BLOCKER  
**Files:** `src/modeling/evidence.py:290-345,375-430`; `tests/architecture/test_modeling_evidence.py:155-225,312-364`; `docs/architecture/provenance.md:40-61`  
**Issue:** The loader accepts any caller-supplied directory whose name is the hash of its own manifest and any erratum that points to that hash. It never compares the manifest, erratum, or source-tree identities with the documented fixed export (`9ac54d58...`), erratum (`c7be7434...`), or producer tree (`c3bbc8c...`). Tests deliberately construct an arbitrary synthetic bundle/erratum and call it `ReportingAuthority`. An attacker can forge metrics, rehash the package, and receive typed authority.  
**Fix:** Pin the canonical manifest, erratum, and source-tree digests in a trusted authority/configuration outside the supplied bundle (or require an independently trusted authority object). Require the exact 12-member package and exact disclosure bytes, and add a test that a self-consistent rehashed synthetic bundle is rejected.

#### CR-14: Metric and comparison claims are not reconciled with the confusion matrix

**Classification:** BLOCKER  
**Files:** `src/modeling/evaluation.py:50-133,191-219`; `tests/architecture/test_modeling_evidence.py:36-65`  
**Issue:** `ModelMetrics` checks supports, accuracy, invalid counts, and two error totals but never recomputes precision, recall, per-class F1, macro F1, or weighted F1. `TwoModelEvaluationResult` checks only comparison-statement prefixes, not whether statements follow the two metric sets. The synthetic accepted fixture already contains precision/recall/F1 values inconsistent with its confusion matrix. Downstream reporting can therefore present mathematically false quantitative claims.  
**Fix:** Derive every metric and comparison statement from the confusion matrix (or validate with a documented tolerance), reject inconsistent supplied values, and test each metric plus deliberately reversed comparison statements.

#### CR-15: Importing runtime eagerly loads the forbidden training module

**Classification:** BLOCKER  
**Files:** `src/runtime/service.py:5-9`; `src/modeling/__init__.py:3-10`; `tests/architecture/test_import_boundaries.py:56-74`; `architecture/module-boundaries.json:220-225`  
**Issue:** `runtime.service` imports `src.modeling.inference`, which first executes `src.modeling.__init__`; that initializer eagerly imports `src.modeling.training`. This violates the explicit runtime-forbidden target and the documentation claim that runtime cannot reach training. The static graph sees only written `Import`/`ImportFrom` nodes and does not model implicit package-initializer edges, so the policy test misses the live reachability. A fresh-process import confirmed `src.modeling.training` is present after importing `src.runtime.service`.  
**Fix:** Make `src/modeling/__init__.py` import-free/minimal and require explicit submodule imports. Model parent-package initialization (and dynamic imports) in the graph, and add a fresh-process assertion that runtime imports leave `src.modeling.training` absent.

#### CR-16: The held-out startup guard ignores keyword path arguments

**Classification:** BLOCKER  
**Files:** `tests/architecture/bootstrap/sitecustomize.py:71-101,121-171`; `tests/architecture/test_provenance_boundary.py:279-344`  
**Issue:** Guard wrappers inspect only positional `args`; `kwargs` is never examined. Calls such as `open(file=...)`, `os.stat(path=...)`, or keyword `src`/`dst` rename variants bypass the guard and reach the underlying filesystem. Existing tests use only positional paths, so the claimed pre-filesystem deny-open proof is incomplete.  
**Fix:** Define per-primitive positional and keyword path names, inspect both forms before delegation, and cover keyword calls during collection and in child processes. Also close or explicitly prohibit unpatched external-process access paths rather than describing this Python monkeypatch as a complete filesystem boundary.

#### CR-17: Runtime doctor treats blocked or missing release evidence as passing

**Classification:** BLOCKER  
**File:** `src/runtime/doctor.py:18,194-225`  
**Issue:** Any successfully parsed release artifact produces `passed=True` regardless of `artifact.verdict`, so `BLOCK` and `FLAG` cannot block overall readiness. The search root is CWD-relative; invoking installed `vnphish doctor` outside the repository commonly finds no artifact and also returns a passing check. The only test covers an incomplete synthetic `PASS`.  
**Fix:** Resolve a configured canonical absolute release-manifest root, define whether absence is a hard failure, and set `passed = artifact.verdict == 'PASS'` only after the strict release contract succeeds. Add `BLOCK`, `FLAG`, missing-root, and non-repository-CWD tests.

#### CR-18: Unsafe recommendations bypass filtering by starting with a “safe” word

**Classification:** BLOCKER  
**File:** `src/runtime/analyzers/local_model.py:41-66,543-547,563-573`  
**Issue:** `_is_unsafe_recommendation()` immediately returns safe for any text beginning with `không`, `tránh`, or `xác minh`. A generated instruction such as “Không lo, bấm vào liên kết...” contains an unsafe action marker but bypasses filtering because of its prefix. This can expose users to precisely the phishing actions the safety filter is meant to remove.  
**Fix:** Scan unsafe actions first and exempt only a syntactically bounded negation of that same action, or use a closed set of generated safe recommendations. Add adversarial mixed-clause Vietnamese and ASCII-diacritic tests.

#### CR-19: The training compatibility route changes frozen error output

**Classification:** BLOCKER  
**Files:** `src/modeling/training.py:29-43`; `src/model_adaptation/commands/adaptation.py:313-377,458-467`; `docs/architecture/cli-contracts.md:21-24,65-66`  
**Issue:** The old CLI called historical `build_training_config`/`run_training` directly and printed their `ValueError`, `FileNotFoundError`, or `RuntimeError` messages. The new service wraps every non-`TrainingError` exception in generic `TrainingError` text, so the compatibility CLI now prints a different message while the phase claims exact output/error preservation. Tests assert the new wrapper behavior separately and use successful handler doubles; they never compare a real failing compatibility handler.  
**Fix:** At the compatibility seam, preserve and rethrow the frozen exception types/messages (or unwrap the cause before the CLI boundary). Add failing backend/config tests that compare return code and stderr with the pre-refactor contract.

#### CR-20: Invalid split ratios can drop records or crash assignment

**Classification:** BLOCKER  
**Files:** `src/config/settings.py:44-52`; `src/data_pipeline/core/splits.py:38-85,88-103,146-180`  
**Issue:** Neither settings nor the public splitter requires nonnegative ratios summing to one. When the sum is below one, `_allocate_split_counts()` distributes at most three residual records and can leave seed IDs unassigned, causing `assignments[seed_id]` to raise. Negative/over-one ratios produce negative or distorted slices. Invalid configuration can therefore lose data or crash a corpus build.  
**Fix:** Validate exactly three finite nonnegative ratios whose sum is one within a documented tolerance in both settings and public split functions. Assert allocated counts sum to the input and every seed receives exactly one assignment.
