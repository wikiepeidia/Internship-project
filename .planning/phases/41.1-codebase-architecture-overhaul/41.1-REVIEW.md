## Summary

Re-reviewed the 3 commits documented in `41.1-REVIEW-FIX.md` (iteration 2 of the fix pass, closing
WR-N1, WR-N2, WR-N3 from the prior `41.1-REVIEW.md`) against current source — not the commit
messages or the fix report's own narrative. Verdict per finding, verified by direct code reading:

- **WR-N1** (`src/runtime/service.py:150-152`, commit `187fedf`) — **closed correctly.** The clamp
  `max_cues = max(0, min(self.settings.runtime_max_cues, 3))` is unconditional on the shared
  `analyze_text()` return path used by both `cli.py` and `demo.py`, so a sub-3
  `RUNTIME_MAX_CUES` override is now honored on the demo server path (which never runs
  `RuntimeDoctor.run()`), and the `min(..., 3)` term also guards an above-3 override even though
  `AnalysisResult.top_cues` already carries a `max_length=3` Pydantic ceiling. Traced negative
  (`runtime_max_cues=-1` → `max_cues=0`, trims to empty) and large (`runtime_max_cues=1000` →
  `max_cues=3`) inputs; both clamp correctly. No regression found.
- **WR-N2** (`src/runtime/render.py:31`, commit `d2dce5e`) — **closed correctly.**
  `_CONTROL_CHARS` changed from `[\x00-\x08\x0b\x0c\x0e-\x1f\x7f-\x9f]` (which skipped `\x0d`) to
  `[\x00-\x08\x0b-\x1f\x7f-\x9f]`. The contiguous `\x0b-\x1f` range now includes `\x0d` (13), so a
  bare carriage return in `summary`/cue `reason`/`recommendations` text is now stripped
  unconditionally, while `\x09` (tab) and `\x0a` (newline) remain intentionally untouched per the
  documented rationale. Confirmed by character-range arithmetic, not just re-running the two
  existing (non-hostile-input) tests.
- **WR-N3** (`tests/runtime/test_demo.py`, commit `3cf3007`) — **closed correctly.** All 5 new
  tests were traced against the actual `_is_same_origin_request`/`_handle_analyze` implementation
  and `wsgiref.util.setup_testing_defaults()`'s real default (`HTTP_HOST` defaults to `SERVER_NAME`
  = `"127.0.0.1"`, no port), confirming `origin="http://127.0.0.1"` in
  `test_demo_api_allows_matching_origin` genuinely matches `_expected_origin()`'s output rather
  than coincidentally passing. All 5 assertions (403/403/400/200/200, `service.called`
  True/False in the right places) match the implementation's actual branch order (Content-Type
  checked before Origin/Referer).

No new critical or security-severity issues were introduced by these 3 commits. Two Info-level
test-coverage gaps remain/emerge (see below); neither indicates the underlying fix is wrong —
both were verified correct by direct code reading — but neither is guarded by a regression test
that would catch a future silent regression.

### IN-N2: WR-N1 and WR-N2 fixes (this pass) also shipped without a test that exercises the specific behavior they fixed

**Files:** `src/runtime/service.py:150-152` (`runtime_max_cues` clamp), `src/runtime/render.py:31`
(`_CONTROL_CHARS` `\x0d` stripping)

**Issue:** Both fixes are correct (see Summary), but neither is covered by a test that would fail
if the fix were reverted:

- `tests/runtime/test_service.py` has no case that sets `settings.runtime_max_cues` below 3 (e.g.
  `1`) and asserts `RuntimeService.analyze_text()` actually trims `result.top_cues` to that length.
  The fix report's "14/14 passed" verification for WR-N1 only confirms no *existing* test
  regressed — none of those 14 tests construct a sub-3 `runtime_max_cues` scenario, so a future
  refactor that silently drops or breaks the clamp (e.g. reintroducing the WR-N1 regression, or
  an off-by-one in the `min`/`max` composition) would not be caught by CI.
- `tests/runtime/test_render.py` still has only the same 2 tests from before this fix (confirmed by
  direct read): one non-hostile multi-field case and one summary-only case. Neither includes a
  `\x0d` (or any control character) in an input field, so nothing in the suite would fail if
  `_CONTROL_CHARS` regressed to the pre-WR-N2 pattern that excluded `\x0d`.

This mirrors IN-N1's pattern one iteration later — the fixer's own "verified: N/N passed" language
in `41.1-REVIEW-FIX.md` is easy to misread as "the fix is regression-tested" when it only means
"the fix didn't break anything pre-existing tests already checked."

**Fix:** Add, at minimum:

    # backend returns 3 cues; settings.runtime_max_cues = 1
    # assert len(result.top_cues) == 1
