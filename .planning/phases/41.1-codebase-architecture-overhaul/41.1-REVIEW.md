# Phase 41.1: Code Review Report

**Reviewed:** 2026-08-27T14:50:43Z
**Depth:** standard
**Files Reviewed:** 40
**Status:** issues_found

## Summary

The post-gap implementation is not ready to seal. The startup safety guard can be
bypassed through callables it exposes itself, misses keyword descriptors and native
process surfaces, and is contradicted by stale provenance tests. The bounded run of
test_provenance_boundary.py produced 13 failures (23 passed); running the five
reviewed architecture files together also failed during collection.

Individually bounded suites that passed were architecture policy 11/11, active
language policy 28/28, report handoff 7/7, and source archiving 28/28. Those isolated
passes do not close the cross-suite and guard defects below.

## Narrative Findings (AI reviewer)

## Critical Issues

### CR-01: The guard publishes direct references to every protected original

**Classification:** BLOCKER

**File:** tests/architecture/bootstrap/sitecustomize.py:27-29,136-176,203-213

**Issue:** _ORIGINALS stores unguarded callables, functools.wraps publishes them as
__wrapped__, and process wrappers additionally publish __phase411_original__.
Collected code can call builtins.open.__wrapped__ or
subprocess.run.__phase411_original__ and bypass the claimed denial. This was
confirmed with synthetic non-protected probes.

**Fix:** Treat OS/process isolation as the actual boundary. At minimum stop retaining
or publishing originals and add adversarial tests for every wrapper escape. Do not
describe an introspectable in-process monkeypatch as a complete security boundary.

### CR-02: Descriptor capability checks ignore keyword arguments

**Classification:** BLOCKER

**File:** tests/architecture/bootstrap/sitecustomize.py:216-234

**Issue:** _make_descriptor_consumer examines positional arguments only. A call such
as os.fstat(fd=unregistered_descriptor) reaches the OS instead of the guard; current
tests exercise only positional descriptors.

**Fix:** Give each descriptor operation an explicit positional-and-keyword signature,
validate all supplied descriptor fields before delegation, and mutation-test both
forms for every available API.

### CR-03: The deny-all process policy is only a self-authored wrapper list

**Classification:** BLOCKER

**File:** tests/architecture/bootstrap/sitecustomize.py:22-24,57-82,286-294,423-443

**Issue:** The implementation calls the policy deny-all but patches only the 53 names
in its own manifest. Owning-module/native alternatives such as nt.system (or
posix.system) and native creation through ctypes remain outside that list. The test
derives its expected set from the same fixture, so omissions cannot be detected.

**Fix:** Enforce process isolation outside Python. If this layer remains as defense
in depth, cover owning primitives and import/reload escapes and add independent
negative probes not derived from _PROCESS_OPERATION_NAMES.

### CR-04: The provenance suite violates and contradicts the guard contract

**Classification:** BLOCKER

**File:** tests/architecture/test_provenance_boundary.py:656-905

**Issue:** The latter suite still expects old error strings and child-process
exceptions, references removed _INHERITED_FDS, launches subprocess.run despite the
deny-all policy, and directly reads protected model/historical authorities at lines
834-881. Under the required guard, the exact file run fails 13 tests. Without the
guard, the baseline test performs access this phase explicitly forbids.

**Fix:** Remove the stale child-process and direct-authority paths. Test denial with
synthetic paths and keep the reviewed Git-metadata-only PowerShell verifier as an
externally invoked bounded gate. Ensure no optional environment flag can re-enable
historical traversal.

### CR-05: Windows bound descriptors make provenance tests fail under the guard

**Classification:** BLOCKER

**File:** tests/architecture/bootstrap/sitecustomize.py:216-239,316-405

**Issue:** Descriptors returned through the Windows msvcrt.open_osfhandle path used
by BoundParent are not registered. Synthetic archive publication reaches
os.fstat/os.close with an unknown descriptor and is denied. Seven provenance archive
tests fail before their intended assertions. A workaround exists only in
test_source_archiving.py:164-182.

**Fix:** Move the reviewed Windows registration shim into the shared architecture
fixture, or expose one narrow post-install registration seam, and add a cross-file
test proving registration occurs after guard installation and is removed on close.

### CR-06: The static-language import guard corrupts combined collection

**Classification:** BLOCKER

**File:** tests/architecture/test_active_language_policy.py:54-99

**Issue:** _IMPORT_GUARD is inserted into global sys.meta_path at module import and
never removed. In the combined bounded run it blocks src.source_archiving while
pytest collects the provenance and source-archiving modules.

**Fix:** Install the finder in a yielding fixture and remove the exact finder in
finally, or isolate these assertions in a dedicated harness. Make the combined
five-file invocation a required gate.

### CR-07: Tool-route discovery fails open on unrecognized execution forms

**Classification:** BLOCKER

**File:** tests/architecture/test_architecture_policy.py:641-774

**Issue:** Python recognizes only subprocess.Popen, batch only python -m src.*,
PowerShell parsing is filename-specific, and bash recognizes one training pattern.
A subprocess.run route or batch powershell -File route derives no edge and can be
added while the inventory stays green.

**Fix:** Parse or reject every supported execution primitive. Fail closed on any
unclassified executable statement and mutation-test run, call, system,
Start-Process, cmd, powershell, and shell-to-shell routes.

### CR-08: Archive verification accepts forged actual mismatch facts

**Classification:** BLOCKER

**File:** src/source_archiving/service.py:254-320,349-370

**Issue:** Receipt parsing validates actual_sha256 only as 64-hex text, while final
verification binds only mismatch paths and expected_sha256 values. An editor can
change an actual hash or timestamp, recompute the unkeyed self-hash, and have
verify_archived_source_closure accept the altered provenance fact.

**Fix:** Bind production receipt bytes to an independent expected digest/Git blob
authority or cryptographically authenticate them. If the self-hash is only an
accidental-corruption check, document that limitation and do not call mutable fields
independently verified.

## Warnings

### WR-01: PRE-to-POST ownership proof is partly synthesized from POST

**Classification:** WARNING

**File:** tests/architecture/test_architecture_policy.py:1202-1374

**Issue:** _pre_extraction_active_text constructs PRE from the current POST fixture,
so both sides can drift together. Pre-rewrite hashes in runtime_prose_contract.json
are format-checked but not tied to immutable Git metadata.

**Fix:** Retain independent PRE and POST manifests and bind PRE paths/hashes to a
fixed commit/blob-OID fixture.

### WR-02: Report scans miss wrapped destructive commands and secret forms

**Classification:** WARNING

**File:** tests/architecture/test_report_handoff.py:76-77,187-194,327-344

**Issue:** Destructive-command detection is anchored to a narrow line start and
secret detection covers few assignment forms. Markdown bullets, prompts, or wrappers
such as powershell -Command Remove-Item can evade it.

**Fix:** Normalize Markdown/prompt prefixes, parse wrapper command tokens, and add
bullet, blockquote, shell-prompt, cmd /c, and PowerShell -Command mutations.

### WR-03: Exact JSON authority readers accept duplicate keys

**Classification:** WARNING

**File:** tests/architecture/test_architecture_policy.py:201-205,519-522

**Issue:** These helpers use permissive json.loads, so duplicate keys in policy or
fixture authorities silently resolve with last-value-wins behavior.

**Fix:** Reuse the strict duplicate-key and non-finite-token parser from
test_report_handoff.py.

### WR-04: Valid malformed demo requests escape as unhandled exceptions

**Classification:** WARNING

**File:** src/runtime/demo.py:95-109

**Issue:** CONTENT_LENGTH is converted before error handling, UTF-8 decode errors are
not caught, and valid JSON scalars/lists are assumed to have .get. These inputs
produce an uncaught exception instead of the documented JSON 400 response.

**Fix:** Validate a bounded non-negative length, catch ValueError,
UnicodeDecodeError, and JSONDecodeError, require a mapping payload, and return one
structured 400 contract.

### WR-05: Arbitrary host binding contradicts the local-only boundary

**Classification:** WARNING

**File:** src/runtime/cli.py:57-73; src/runtime/demo.py:147-160; README.md:53-70

**Issue:** The CLI accepts any --host and starts an unauthenticated HTTP endpoint,
while active documentation describes the runtime as local-only. Binding to 0.0.0.0
or a LAN address silently crosses that boundary.

**Fix:** Reject non-loopback hosts by default. If network exposure is needed, require
an explicit opt-in with authentication and a privacy warning, then update the public
contract.
