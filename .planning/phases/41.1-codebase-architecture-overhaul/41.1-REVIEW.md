## Critical Issues

### CR-01: Dataset JSON ingress silently changes or discards record facts

**Classification:** BLOCKER  
**Files:** `src/data_pipeline/core/records.py:16-28,102-205`; `src/data_pipeline/workflows.py:55-63,88-93`
**Issue:** The boundary models use Pydantic's permissive defaults, and both JSONL readers call `model_validate_json()` directly. Duplicate JSON keys therefore use the last value, unknown fields are silently discarded, scalar coercion is enabled, and whitespace-only seed text can satisfy the raw length floor. A synthetic seven-field row containing `"label":"task_scam"` followed by `"label":"benign"` validated as benign; an extra provenance field disappeared; `ManifestFile(records=True, ...)` became one; and a twelve-space seed was accepted. Contradictory or contaminated input can consequently enter the corpus without an auditable rejection.
**Fix:** Give every ingress model a closed configuration (`extra="forbid"`) and strict integrity fields, add nonblank validators to seed facts, and route all JSONL through one strict UTF-8 object decoder that rejects duplicate keys, non-finite tokens, non-object rows, and partial records before Pydantic validation. Include the source path and line number in every rejection.

### CR-02: Nested output-parent creation can mutate outside the trusted root

**Classification:** BLOCKER  
**File:** `src/core/integrity.py:298-319`
**Issue:** `prepare_bounded_output()` validates ancestry and then creates each missing directory with path-based `current.mkdir()`. An existing ancestor can be renamed and replaced by a symlink or Windows junction between loop iterations. The next `mkdir()` then mutates the redirect target before the final identity check notices the swap. This undermines callers that rely on this helper before entering the newer bound writer.
**Fix:** Bind the trusted root once and create every descendant component through descriptor-relative or Win32 handle-relative no-follow operations. Verify the currently bound parent before and after each creation, retain exact created identities for cleanup, and never issue a path-based mutation after the initial check.

### CR-03: The preserved validated-record publisher can destroy coherent live state

**Classification:** BLOCKER  
**Files:** `src/data_pipeline/workflows.py:64-87`; `src/data_pipeline/cli.py:209-216`
**Issue:** `_save_validated_records()` remains deliberately callable through the compatibility CLI. It follows ordinary path ancestry, uses predictable `.tmp` names, replaces the fixed live `validated.jsonl`, and only afterward serializes and replaces `quality-stats.json`. A serialization or second-publication failure leaves new rows paired with stale statistics, while the prior rows have already been replaced. A reparse parent can also redirect these writes.
**Fix:** Remove the compatibility seam or implement it as a shim over the immutable-generation publisher. Stage and validate both artifacts below a bound root, publish the complete generation, then switch exactly one atomic current pointer; never replace either live member independently.

### CR-04: Dataset manifest members are reopened after their containment check

**Classification:** BLOCKER  
**File:** `src/data_pipeline/core/splits.py:194-225,246-247,267-278`
**Issue:** `_manifest_jsonl_paths()` validates member ancestry while enumerating, but `_jsonl_facts()` later calls `Path.read_bytes()` on each pathname. A regular member can be replaced by a symlink or reparse target between those operations. Manifest construction can hash external bytes, and verification can read external bytes and accept them when the stored facts match.
**Fix:** Capture every member through `read_file_bytes()` or a root-bound descriptor/handle, preserve the inspected root and member identities through enumeration and capture, and recheck exact root membership after all bytes are captured.

### CR-05: The held-out deny-open guard still permits unguarded child processes

**Classification:** BLOCKER  
**File:** `tests/architecture/bootstrap/sitecustomize.py:149-180` (coverage gap at `tests/architecture/test_provenance_boundary.py:453-519`)
**Issue:** The subprocess wrapper checks only that a Python child sees the bootstrap directory in `PYTHONPATH`. It does not require `PHASE411_DENY_OPEN_SENTINEL=1`, accepts `-S`, `-I`, and `-E`, ignores an `executable=` override, and uses `kwargs.get("env") or os.environ`, so an explicitly empty environment is validated as the parent environment. A guarded probe successfully launched `python -S` with `sitecustomize` absent, and another launched a normal child with the bootstrap importable but `PHASE411_GUARD_INSTALLED=False`. Unwrapped pathname APIs such as `os.access`, links, and metadata mutators remain available as well. The broad Git-verb allowance also lacks an exact argument grammar.
**Fix:** Fail closed on explicit environment replacement, require the child sentinel and bootstrap, reject interpreter flags that disable site or environment processing, reject executable overrides, and allow only exact reviewed child command grammars. Patch or categorically prohibit every remaining pathname API used by the test process, and add adversarial tests that attest guard installation inside each allowed child.

### CR-06: Coordinated unsafe actions still pass the recommendation filter

**Classification:** BLOCKER  
**File:** `src/runtime/analyzers/local_model.py:544-580` (incomplete cases at `tests/architecture/test_runtime_boundaries.py:477-506`)
**Issue:** Once the first unsafe verb is negated, the parser treats later verbs joined by `và`, `hoặc`, `hay`, or their ASCII forms as covered by the original negation unless one of a short pivot list appears. The phrases “Không bấm vào liên kết và nhớ chia sẻ OTP cho họ”, “Không bấm vào liên kết hoặc hãy chuyển tiền để xác minh”, and “Không bấm vào liên kết và sau đó cài ứng dụng này” all returned safe. A generated recommendation can therefore instruct the user to expose credentials, transfer money, or install an app.
**Fix:** Parse each unsafe action as its own bounded verb phrase and require an explicit local negation for every occurrence. Treat imperative markers such as `hãy`, `nhớ`, `sau đó`, and unknown coordination as unsafe; when scope cannot be established, fail closed and substitute the fixed safe recommendations. Add all reproduced cases to the architecture test.

### CR-07: The OTP-notice heuristic can overwrite an explicit high-risk payment result

**Classification:** BLOCKER  
**File:** `src/runtime/analyzers/local_model.py:651-733`
**Issue:** `_looks_like_legitimate_bank_otp_notice()` uses a small substring allow/deny heuristic, then `_downgrade_legitimate_otp_notice()` unconditionally replaces the model decision before the safety floor. Its unsafe marker list omits payment instructions. A synthetic message containing a bank name, OTP, “khong chia se”, and “Chuyen tien 5 trieu ngay” was supplied with grounded high-risk payment evidence but returned `benign` with no cues. The heuristic can erase a correctly detected scam.
**Fix:** Never let a heuristic downgrade an explicit grounded high-risk decision. Require an exact safe-notice structure and absence of every credential, payment, urgency, URL, contact-takeover, and helper cue before considering a downgrade; otherwise preserve or elevate the decision. Add mixed legitimate-language/payment cases to the runtime contract.

### CR-08: Untrusted model output can remove the provisional-analysis warning

**Classification:** BLOCKER  
**File:** `src/runtime/analyzers/local_model.py:155-183,675-743,753-766`
**Issue:** The local output contract defaults `provisional=True`, but `_build_threat_decision()` accepts `payload["provisional"]` from the generated model and propagates it to the user-facing `AnalysisResult`. A synthetic otherwise valid model payload with `"provisional": false` produced a non-provisional result. A model response is not an authority to certify its own local risk assessment.
**Fix:** Remove `provisional` from the model-controlled schema and force `True` at the active local-runtime boundary. If a future authoritative workflow can clear the flag, expose a separate typed, externally verified transition rather than accepting generated JSON.

## Warnings

### WR-01: A release manifest can certify malformed JSONL

**Classification:** WARNING  
**File:** `src/data_pipeline/core/splits.py:219-225`
**Issue:** `_jsonl_facts()` checks strict UTF-8 but counts any nonblank line. Malformed JSON, arrays, duplicate-key objects, and schema-invalid rows can receive valid hashes and record counts in a dataset release manifest.
**Fix:** Parse every nonblank line with the strict JSONL decoder during both build and verification, require an object, and apply the intended record schema for dataset-release members.

### WR-02: A valid zero-gap recovery request crashes while building its summary

**Classification:** WARNING  
**File:** `src/data_pipeline/workflows.py:257-264,312-345,507-510`
**Issue:** A recovery target of zero is explicitly valid. In that branch no publication is produced, so `merged_output_path` is `None`; `build_training_corpus(..., gap_fill_recovered=True, generate_only=True)` then evaluates `Path(None)` while returning the no-gap summary.
**Fix:** Let `_generate_only_summary()` accept `Path | None` and serialize a missing generated path as `None`, or point to an independently verified existing recovery artifact. Add an exact zero-gap regression test.
