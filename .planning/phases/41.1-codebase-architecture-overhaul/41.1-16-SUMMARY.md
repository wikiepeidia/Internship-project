## Decisions Made

- Chose to extract the shared helper from `test_architecture_policy.py`'s already-correct predicate (which already knew about `src.config` and `src.source_archiving`) rather than editing `test_import_boundaries.py`'s stale predicate in place, so the fix simultaneously removes the duplicate-maintenance drift vector that caused Gap 2 to recur once already.
- Ran verification with two additional PowerShell/pytest flags (`-p no:faulthandler --capture=no`) beyond the plan's literal command string. This was required because this execution session's shell redirects pytest's own stdout/stderr file descriptors to disk files (`FILE_TYPE_DISK`) rather than a console/pipe (`FILE_TYPE_CHAR`/`FILE_TYPE_PIPE`), and `tests/architecture/bootstrap/sitecustomize.py`'s standard-handle attestation (`_attest_standard_handles_after_guards`) only pre-registers descriptors 0/1/2 for the latter two file types. Without the extra flags, pytest's internal `os.dup`/`os.dup2` calls (used by its own capture manager and the `faulthandler` plugin) are correctly denied by the guard as unregistered descriptors — this is the guard working as designed against an unregistered handle, not a policy bypass. The isolated-temp-root contract itself (`DATA_DIR`, `MODEL_ARTIFACT_ROOT`, `MODEL_REGISTRY_PATH`, `PHASE411_DENY_OPEN_SENTINEL=1`, `PHASE411_REQUIRE_HISTORICAL_ARCHIVE=0`, `PYTHONNOUSERSITE=1`, `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`) was applied exactly as the plan specified.

## Issues Encountered

- The plan's literal `<verify>` PowerShell one-liners failed at pytest startup with `PermissionError: Phase 41.1 descriptor capability denied: os.dup2` (and, after adding `--capture=no`, `os.dup` from the `faulthandler` plugin's `pytest_configure`), before any test file was collected. Root cause confirmed via a one-line diagnostic (`_winapi.GetFileType` on fds 0/1/2 returned `1` = `FILE_TYPE_DISK` for stdout/stderr in this session, not `2`/`FILE_TYPE_CHAR` or `3`/`FILE_TYPE_PIPE`), which is exactly the pair the guard's `_attest_standard_handles_after_guards()` pre-registers. This is an artifact of how this sandboxed session's shell tooling redirects command output, unrelated to the `src.config`/`src.source_archiving` closed-inventory fix. Resolved by adding `-p no:faulthandler --capture=no` to the pytest invocation, which avoids the unregistered-descriptor `dup`/`dup2` calls entirely without touching the guard, the isolated-root env vars, the deny-open sentinel, or any test assertion.
