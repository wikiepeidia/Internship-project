# Phase 41.1 — Security

> Per-phase security contract for the architecture overhaul. This register verifies only the threats authored in the six Phase 41.1 plans; it does not claim that unrelated project risks were audited.

---

## Trust Boundaries

| Boundary | Description | Data crossing |
|---|---|---|
| Frozen repository manifest → clean runtime | Runtime source must match an immutable membership and hash authority. | Source code and provenance metadata |
| Captured source → historical mirror | Redirects, races, overwrites, and provenance relabeling fail closed. | Source bytes and receipts |
| CLI arguments → lazy route table | User input selects only reviewed literal commands. | Command tokens |
| Filesystem artifacts → runtime | JSON, paths, manifests, and model identities are validated before use. | Untrusted artifact metadata |
| Environment → settings owners | Components receive only their owned settings and do not expose secrets. | Configuration and credentials |
| Active modeling → legacy adapters | Only reviewed, lazy, fixed-direction compatibility edges may cross. | Model requests and results |
| Frozen export → report reader | Report-facing APIs verify evidence without exposing predictions or held-out records. | Metrics, hashes, and report-safe summaries |
| Synthetic records → data transforms | Strict schemas and deterministic transforms reject malformed data before publication. | Dataset records and manifests |
| Checked architecture → report documents | Narrative claims must be mechanically traceable and correctly qualified. | Architecture and provenance facts |
| Storage inventory → retention guidance | Documentation must remain non-destructive and require separate authorization for cleanup. | Paths, sizes, and retention policy |
