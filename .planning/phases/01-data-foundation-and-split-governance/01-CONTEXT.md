# Phase 1: Data Foundation and Split Governance - Context

**Gathered:** 2026-04-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Build a reproducible, versioned Vietnamese financial phishing dataset pipeline: scrape seed threats from Vietnam NCSC, expand to 2K-3K synthetic JSONL samples via tiered LLM generation, and enforce contamination-free train/eval splits with seed-level governance and semantic dedup.

**Timeline constraint:** Project has 1-month total timeline with 3-day supervisor report cadence. Phase 1 should produce reportable deliverables every ~3 days (scraper + seeds, then synthetic pipeline, then versioned splits).

</domain>

<decisions>
## Implementation Decisions

### Seed Collection (Multi-Source)
- **D-01:** Python-based scraper using BeautifulSoup or Playwright with a unified extractor interface — base class with `extract(url) -> SeedRecord[]`. Each source is a subclass with its own CSS selectors. Adding new sources = adding a new config/subclass.
- **D-02:** Implement polite scraping with randomized delays to respect rate limits and avoid IP blocks on all sources.
- **D-03:** Target 100-300 usable seed examples total across all sources. Once target is reached from any combination of sources, stop.
- **D-04:** Waterfall priority source order:
  1. **khonggianmang.vn** (NCSC primary portal) — threat advisories with embedded phishing payloads
  2. **chongluadao.vn** (community-driven) — massive Vietnamese scam/phishing link tracker, goldmine for raw message seeds
  3. **tinnhiemmang.vn** (NCSC secondary portal) — fake banking domain alerts, scam notifications
  4. **VnExpress / Tuổi Trẻ** ("Lừa đảo trực tuyến" tag) — newspaper articles with exact quotes of scam SMS/Zalo messages
  Try each in order. If a source is down or yields too few, move to next. Aggregate all that work.
- **D-05:** Output language is Vietnamese with natural code-switching — English fintech loanwords (OTP, Internet Banking, Smart OTP, link, login, app, account) and Vietnamese teencode/SMS shorthand must be preserved, not normalized away. This matches real-world phishing linguistic distribution.

### Synthetic Data Generation
- **D-06:** Tiered generation approach — Claude API for high-quality expansion of complex examples; cheaper models (DeepSeek via Colab, OpenRouter) for bulk simple variations. Best quality-to-cost ratio.
- **D-07:** User has Claude API access. Does NOT have OpenAI API key. Budget-conscious — prefer free/cheap alternatives for bulk generation.
- **D-08:** Generation prompts must explicitly instruct the LLM to naturally code-switch and use common abbreviations, matching real Vietnamese SMS/social media linguistic patterns.
- **D-09:** Quality validation: LLM-as-judge scores each sample on realism, label correctness, and code-switch naturalness, plus manual spot-check of random 5-10% subset.
- **D-10:** Balanced class distribution across all threat classes (bank impersonation, Zalo social engineering, task scam, etc.) plus robust benign class. Do NOT weight by real-world frequency — balanced training maximizes recall across all classes. Real-world imbalance is addressed at evaluation (Phase 5).

### Dataset Schema (XAI-Optimized JSONL)
- **D-11:** Rich schema per record, designed for downstream XAI instruction tuning:
  - `text`: Raw, code-switched phishing/benign message
  - `label`: Precise threat class (e.g., `bank_impersonation`, `zalo_social_engineering`, `benign`)
  - `risk_tier`: Contextual severity (benign/suspicious/high-risk) — generated by Teacher model, NOT derived from label. Same label can have different risk tiers based on semantic context.
  - `suspicious_spans`: Array of exact substrings for anomaly localization training (e.g., `["http://vpbank-update.vip", "nhap vao link"]`)
  - `xai_explanation`: Localized draft explanation from Teacher model (psychological hook, fake domain analysis, etc.) — critical for final user-facing XAI output
  - `source`: Provenance tag (`ncsc_seed`, `synthetic_claude`, `synthetic_deepseek`)
- **D-12:** Risk tier is contextual and must be an explicit field, not a static label-to-tier lookup. Two messages with the same threat label can have different risk tiers based on semantic severity.

### Versioning & Split Governance
- **D-13:** Store JSONL files directly in Git repository (dataset is <10MB at 3K records). No DVC or external hubs — proprietary data governance.
- **D-14:** Version via git commit tags + SHA256 hash manifests for mathematical integrity verification before any LoRA fine-tuning run.
- **D-15:** Default split ratio: 80/10/10 (train/validation/test), adjustable based on final dataset size. Multiple evaluation runs if feasible.
- **D-16:** Seed-level splitting is MANDATORY — all synthetic variants of a seed must stay in the same split to prevent near-duplicate leakage.
- **D-17:** Semantic similarity check (lightweight embedding model or cosine similarity) across splits AFTER seed-level splitting, to detect and purge semantically overlapping records between train/eval/test. Belt-and-suspenders leakage prevention.

### Claude's Discretion
- Specific scraping library choice (BeautifulSoup vs Playwright) based on NCSC site structure
- Exact LLM-as-judge prompt design for quality validation
- Choice of lightweight embedding model for cross-split dedup
- Threshold tuning for semantic similarity dedup

</decisions>

<specifics>
## Specific Ideas

- Real Vietnamese phishing heavily uses English fintech terminology (OTP, Internet Banking, Smart OTP) and teencode (SMS shorthand) — synthetic generation must replicate this
- The `xai_explanation` field captures Teacher model reasoning at generation time, creating instruction-tuning pairs for the Student (LoRA) model — this is a pipeline design choice, not an afterthought
- Risk tier is contextual: initial contact vs. funds demand can share a label but differ in severity
- Data leakage prevention is the #1 validation risk — seed-level splitting + semantic dedup is non-negotiable

</specifics>
