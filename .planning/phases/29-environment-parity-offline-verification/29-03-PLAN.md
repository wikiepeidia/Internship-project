<objective>
Fix the CWD-relative `.env/.env` model-path fragility by setting `MODEL_ARTIFACT_ROOT` and `MODEL_REGISTRY_PATH` as permanent Windows user-level environment variables via `setx`, per the locked decision D-03 (not a launcher script — `setx` works from any terminal/shortcut forever with zero per-launch discipline required).

Purpose: `Settings` (pydantic-settings) currently resolves these two paths from `.env/.env`, which is discovered relative to the current working directory — launching `vnphish` from any folder other than the repo root silently falls back to the wrong (repo-relative, non-existent) model path. This was identified as the single highest-risk portability issue in Phase 28's research. `setx`'s effect is confirmed (Microsoft docs, cross-verified by direct testing in 29-RESEARCH.md) to apply only to terminal windows opened *after* it runs, never the one that ran it — so the functional proof needs a genuinely new terminal, which this plan hands to a human checkpoint rather than guessing whether an automated shell invocation counts as "new."
Output: two permanent OS-level environment variables, a registry-level proof they were written correctly, and a human-confirmed cross-directory `vnphish doctor` run in a new terminal.
</objective>
