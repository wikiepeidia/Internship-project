## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Codex CLI (external, human-run) -> `data/processed/codex-judge-pass.jsonl` | Semi-trusted external tool output, parsed as untrusted structured input by `judge_merge.py` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-39-01 | Tampering | `load_judge_results()` | medium | mitigate | Every judge-output line is Pydantic-validated (`CodexJudgeResult`, 1-5 score bounds, required fields); a malformed/truncated line (e.g. a crashed Codex batch write) raises `ValueError` naming the line number instead of being silently skipped or coerced. |
| T-39-02 | Tampering | `merge_judge_results()` | high | mitigate | A judge row whose `seed_id` does not match the real source row at that `split`/`row_index` (e.g. a stale judge file re-run against a corpus that changed after a future repair) would silently corrupt the join and produce false-confidence stats cited in the report; `merge_judge_results()` hard-fails on any mismatch instead. |
| T-39-03 | Repudiation | `compute_aggregate_stats()` | low | mitigate | Codex could mis-declare `pass` inconsistently with its own documented ">=3 on all five" rule; `recomputed_pass` is computed independently from the raw scores and `pass_mismatch_count` surfaces any disagreement before the numbers are cited in the report, rather than trusting Codex's self-reported verdict blindly. |
| T-39-04 | Denial of Service | `load_judge_results()` / `load_source_splits()` | low | accept | An oversized or heavily line-malformed input file could slow line-by-line parsing; input is local and human-supervised (the user runs Codex and reports the file back), bounded by the corpus's known 2,421-row scale, and uses the same streaming JSONL pattern already used safely throughout this codebase. |
