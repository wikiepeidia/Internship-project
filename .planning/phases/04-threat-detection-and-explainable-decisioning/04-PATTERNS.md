# Phase 4: Threat Detection and Explainable Decisioning - Patterns

## Summary

The Phase 4 docs in [04-CONTEXT.md](.planning/phases/04-threat-detection-and-explainable-decisioning/04-CONTEXT.md), [04-AI-SPEC.md](.planning/phases/04-threat-detection-and-explainable-decisioning/04-AI-SPEC.md), and [04-RESEARCH.md](.planning/phases/04-threat-detection-and-explainable-decisioning/04-RESEARCH.md) all point to the same implementation seam: extend the existing local runtime rather than adding a new subsystem. The strongest pattern is to keep [src/runtime/service.py](src/runtime/service.py#L84) as the normalize-first, fail-closed boundary, move richer decision semantics into [src/runtime/analyzers/local_model.py](src/runtime/analyzers/local_model.py#L13), keep [src/runtime/analyzers/gguf.py](src/runtime/analyzers/gguf.py#L76) and [src/runtime/analyzers/accelerated.py](src/runtime/analyzers/accelerated.py#L126) thin, and preserve the public contract and operator surfaces in [src/runtime/contracts.py](src/runtime/contracts.py#L43), [src/runtime/render.py](src/runtime/render.py#L6), [src/runtime/cli.py](src/runtime/cli.py), and [src/runtime/doctor.py](src/runtime/doctor.py).

No new source module is strongly implied by the current docs. The planning signal is additive change in existing runtime files plus expanded runtime tests.

## Cross-Cutting Pattern Decisions

- Keep the public runtime result additive, not replacement-based. The docs explicitly preserve the existing compatibility boundary, and the current contract plus tests are built around that assumption.
- Put richer threat labels, grounded evidence, and safe recommendations in the shared local-model layer first. Both real backends already converge through that helper, so it is the correct place to enforce consistency.
- Keep GGUF and accelerated analyzers thin. Their responsibility is local model loading and deterministic generation, not independent post-processing policy.
- Preserve the service, CLI, render, and doctor surfaces. Phase 4 improves decision quality on top of those entrypoints instead of replacing them.
- Treat privacy and local-only behavior as hard constraints, not optional cleanup. Existing privacy tests already encode the repository's expected stance.
- Use the heuristic rule catalog as a deterministic helper only. The research doc treats it as a safety floor and evidence extractor, not as the main Phase 4 decision engine.
