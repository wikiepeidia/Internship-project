## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| held-out records -> runtime evaluation harness | offline scoring must use the public Phase 4 runtime surface instead of raw backend payloads |
| runtime outputs -> metric engine | multilabel predictions and zero-support labels must remain explicit through metric computation |
| overall F1 reporting -> later gate logic | averaged metrics must not hide label-specific recall misses on risky classes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Integrity | src/model_adaptation/release_evaluation.py | mitigate | Evaluate only `AnalysisResult` outputs from the Phase 4 runtime boundary per D-09, not analyzer-private payloads or training-only artifacts. |
| T-05-02-02 | Tampering | metric computation | mitigate | Pass the full locked label order explicitly to `scikit-learn` and preserve zero-support labels instead of letting the library infer a smaller set. |
| T-05-02-03 | Repudiation | evaluation-row provenance | mitigate | Record backend identity, evaluated split metadata, and channel assumptions for each batch so later artifacts can explain what was actually scored. |
| T-05-02-SC | Tampering | multilabel outputs | mitigate | Compute explicit-label metrics without collapsing `AnalysisResult.threat_labels` to one “winning” label. |
</threat_model>
