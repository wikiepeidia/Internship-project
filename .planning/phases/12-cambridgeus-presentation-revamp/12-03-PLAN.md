        Pitfall 2: \section before agenda → header shows wrong section on agenda slide
        Pitfall 3: missing bracket form → footer overflow

  <action>
    Run XeLaTeX twice (required for ToC and cross-references to resolve):
      cd documents/reports/latex && xelatex -interaction=nonstopmode slides.tex
      cd documents/reports/latex && xelatex -interaction=nonstopmode slides.tex

    After each run, scan the .log file for:
      ERROR patterns: "!" prefix lines, "Emergency stop", "undefined control sequence"
      OVERFLOW patterns: "Overfull \vbox", "Overfull \hbox"
      WARNING patterns (acceptable to leave): "Package hyperref Warning", "Token not allowed"

    For each ERROR found, apply the fix:
      - "undefined control sequence \usetheme" → verify packages.tex does not load metropolis
      - "Undefined control sequence \textcolor" → xcolor not loaded; check packages.tex
      - "Argument of \@framef has extra }" → [fragile] is missing from 10_demo.tex; restore it
      - "unknown beamer color 'progress bar'" → Metropolis key remains; remove from slides.tex
      - Fatal TikZ error in figure file → check that \begin{tikzpicture} is not inside \begin{figure}

    For each OVERFLOW found, apply the fix using the tier policy (D-15/D-16):
      Tier 1 — cut text: reduce bullet length, remove sub-bullets
      Tier 2 — split frame: add a second \begin{frame} in the section file
      Tier 3 — font size: add \small or \footnotesize as last resort
      NOTE: scalebox adjustments for figure slides are the first action for
      04_architecture, 06_why_local, 08_evaluation, 09_confusion.

    For \tableofcontents overflow in 02_agenda: if section names wrap to 2 lines, add to
    slides.tex preamble (after \setbeamerfont{section in head/foot}):
      \setbeamerfont{section in toc}{size=\small}

    After applying fixes, run XeLaTeX a third time if any changes were made:
      xelatex -interaction=nonstopmode slides.tex

    Final compile must produce ZERO errors. Warnings about hyperref, token not allowed in
    PDF strings, or "Package rerunfilecheck Warning" are acceptable.
  </action>
