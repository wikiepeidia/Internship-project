# Phase 6 Plan 01: Local demo UI

Objective: deliver one minimal local demo interface for non-technical users that wraps the existing runtime contract without adding OCR, cloud fallback, or a separate frontend stack.

Must haves:

- A user can launch one local demo surface and paste suspicious text without CLI syntax.
- The demo must present risk tier, threat labels, grounded cues, and safe next steps from the existing runtime contract.
- The demo must stay text-only and local-first.
- The implementation must reuse the existing runtime service instead of duplicating analysis logic.

Artifacts:

- `src/runtime/demo.py` provides a local WSGI demo app and server runner.
- `src/runtime/demo_assets/` provides separate HTML, CSS, and JS assets.
- `src/runtime/cli.py` exposes a `demo` command on the existing `vnphish` runtime surface.
- `tests/runtime/test_demo.py` and `tests/runtime/test_cli.py` lock the demo surface before implementation drift.

Verification:

- `python -m pytest tests/runtime/test_demo.py tests/runtime/test_cli.py -q`
- `python -m src.runtime.cli demo --host 127.0.0.1 --port 8765 --no-browser`

Success criteria:

- The demo opens a local page that serves separated HTML, CSS, and JS assets.
- The page can submit pasted text to the runtime and render the contract fields in a zero-prompt flow.
- The implementation keeps the existing runtime boundary and fail-closed behavior intact.
