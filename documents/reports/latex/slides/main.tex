% ============================================================== 3. the data ==
\section{The Data}

\begin{frame}{III. Seed Crawl}
  \framesubtitle{Public scam warnings}
  \begin{itemize}\itemsep 4pt\footnotesize
    \item<2-> A crawler collected warnings from \textbf{tinnhiemmang.vn}, a site that publishes public scam warnings
    \item<3-> Each article becomes a \textbf{seed} with its own ID
    \item<4-> A seed describes a scam. It is \textbf{not} a scam message, so it cannot be training data as it is
    \item<5-> \textbf{Purpose of a seed:} one fixed prompt for Claude, with a different real scam warning dropped in each time. No need to write hundreds of separate prompts
  \end{itemize}
  \vspace{4pt}
  \onslide<6->{%
  \centering
  \includegraphics[width=0.88\linewidth]{seed_row_slide.png}\\[2pt]
  {\scriptsize One row of the retained seed file: the text, the address it came from, the time it was collected}}
  \note{Report 3.2. The prompt is one template with a slot called seed text anchor; only the seed changes between requests. If asked how many: the site has 74 advisory articles and 67 are used (report Chapter II); do not quote any other seed count. Do not say these are scam messages; they are warnings about scams.}
\end{frame}

\begin{frame}[t]{IV. Data Generation}
  \framesubtitle{Seeds to messages}
  \centering
  \resizebox{0.97\linewidth}{!}{\input{figures/data_reveal}}
  \vspace{3pt}
  \only<7-10>{%
  \begin{itemize}\itemsep 5pt\footnotesize\raggedright
    \item<7-> Each message gets its \textbf{label} when it is generated: the prompt names the class
    \item<8-> The first pass was generated by Claude. A large part of it was not usable
    \item<9-> For example, 240 Zalo messages were third-person narration, not real chat. They were rebuilt
    \item<10-> In total, 3,413 messages went into cleaning. About 1,300 did not meet the requirements and were dropped or rewritten, leaving 2,097
  \end{itemize}}
  \only<11->{%
  \includegraphics[width=0.72\linewidth]{corpus_sample.png}\\[2pt]
  {\scriptsize One generated record: all seven fields, the label included}}
  \note{Report 3.2 to 3.3 and Chapter IV. If asked where the rest went: 3,413 minus 2,097 is 1,316. That covers 825 narrated Zalo rows replaced by 300 rebuilt ones, 371 near-duplicates, 94 rows over the 8 percent seed cap, and the label review (91 dropped, and 176 quarantined, meaning taken out, because they all came from one article). Never say every message came from Claude: the raw pool also held a second model's output that filled gaps in some classes. The judge was a GPT-family model. The Zalo rebuild came from a GPT-family model, so the judge is not independent for that class.}
\end{frame}

% ============================================================ 6. conclusion ==
\section{Conclusion}

\begin{frame}{XII. Conclusion}
  \framesubtitle{Findings}
  \begin{itemize}\itemsep 10pt\small
    \item<2-> PhoBERT scored a bit higher than Qwen (0.991 against 0.980, one run each), but it only returns a label
    \item<3-> Qwen gives an explanation with quoted phrases and advice, not only a score
    \item<4-> QLoRA training for Qwen and full-weight training for PhoBERT both ran on the same laptop
    \item<5-> A dataset of 2,097 messages, and one final evaluation on messages neither model had seen
  \end{itemize}
  \note{Report Chapter VI. Bullets 1 to 3 answer the three questions on the first slide (not in that order: 1 and 2 together are the direct answer to why Qwen ships despite the lower score, then 3 is fine-tuning on one machine).}
\end{frame}

\begin{frame}{XIII. Limitations}
  \framesubtitle{Known weaknesses}
  \begin{alertblock}{Project Limitations}
    \begin{itemize}\itemsep 4pt\small
      \item<2-> The messages are generated from public warnings, not collected from real victims
      \item<3-> One run and one seed only
      \item<4-> The judge is from the same GPT family as the model that rebuilt the Zalo messages
      \item<5-> Manual checking covers only a small sample
      \item<6-> Qwen's explanation was never scored on its own, only the label
    \end{itemize}
  \end{alertblock}
  \note{Report Chapter VI and Appendix. Reading these out is cheaper than being walked into them. Not on the slide, but still true and in the report: a code review left six critical findings open. If anyone asks whether this is production-ready or secure, the answer is no. The last item is the one to lead with if asked what you would change: the real contribution here is comparing a classifier against an instruction-tuned LLM on the same task, not shipping an LLM product. Evaluating the explanation text itself, not just the label it agrees on, is future work, and it belongs with the Future Work slide's first item (review the whole dataset by hand) and the ViSoBERT comparison.}
\end{frame}

\begin{frame}{XIV. Future Work}
  \framesubtitle{Next steps}
  \begin{block}{Project Future Work}
    \begin{enumerate}\itemsep 8pt\small
      \item<2-> Review the whole dataset by hand
      \item<3-> Use both models together: PhoBERT for the label, Qwen for the explanation
      \item<4-> Train and evaluate ViSoBERT (Nguyen et al., 2023), a model built for Vietnamese social-media text
      \item<5-> Add OCR, so a screenshot can be the input
    \end{enumerate}
  \end{block}
  \note{Report Chapter VI. The second item is also the answer to why Qwen is shipped when PhoBERT scored higher. ViSoBERT is the reference on the References slide; the report says it was trained on social-media text and reported better results than PhoBERT on informal Vietnamese tasks, spam detection included.}
\end{frame}

\begin{frame}{Backup: A Genuine Message the System Gets Wrong}
  \framesubtitle{False alarm}
  \begin{block}{Input}
    \scriptsize VPBank Smart OTP: Mã xác thực của bạn là 847291. Mã này có hiệu lực trong 90 giây để xác nhận đăng nhập Internet Banking. Tuyệt đối KHÔNG chia sẻ mã này với bất kỳ ai, kể cả nhân viên ngân hàng.
  \end{block}
  \begin{itemize}\itemsep 5pt\small
    \item The system returned \textbf{suspicious}, label bank impersonation. The right answer is benign
    \item Six ordinary bank messages tried: four returned benign. The two flagged are the only two that ask the reader to log in
    \item Nearly every scam in the training data asks someone to log in or hand over a code, so the model treats that wording as the signal
    \item It is the safer direction: a false alarm costs a minute, a missed scam can cost savings. The advice was still safe
  \end{itemize}
\end{frame}
