This thesis developed a local LLM pipeline for Vietnamese financial phishing detection. The system connects synthetic data construction, Pydantic schema constraints, QLoRA adaptation, GGUF deployment, and structured user-facing output in one reproducible prototype.

\section{Main Findings}
The deployed model is \texttt{Qwen3-4B-Instruct-2507}, adapted with 4-bit NF4 QLoRA on 2{,}333 training examples in the earlier 3{,}000-row training snapshot. On that snapshot's 254-example internal validation split, the adapted model reaches macro F1 0.9625 and accuracy 0.9646, compared with macro F1 0.6702 for the same base model without adaptation. The nine remaining errors are all between scam subtypes; none cross the binary scam--benign boundary. These historical model metrics were not recomputed on the promoted 2{,}097-row corpus. The merged Q8\_0 GGUF is registered and has been verified through the CPU-only command-line runtime.

These results support two limited conclusions. First, parameter-efficient adaptation substantially improves this model on the project's validation rows. Second, the full local deployment path is technically feasible on the target laptop. The results do not establish performance on independent real-world traffic.

\section{Limitations}
Several structural constraints bound the evaluation claims. First, the architecture is strictly text-only; it does not process screenshots, QR codes, audio, or multi-turn conversations. Second, the corpus is Vietnamese-only and synthetic-derived, so generalization to real user traffic or other languages is unverified. Third, the current 2{,}097-row corpus is not the snapshot used to produce the historical 254-row model comparison. The promoted corpus instead contains 1{,}658 training, 219 validation, and 220 test rows, and new model evidence must preserve that held-out boundary rather than transferring older metrics to it. The system should consequently be treated as an academic prototype rather than an autonomous safety tool.

\section{Ethical Considerations}
Two considerations follow directly from what this system does and does not do. First, a model that recognizes scam patterns well necessarily encodes knowledge of what those patterns look like; the deployed contract constrains this to a detection-only output (risk tier, labels, grounded cues, safe recommendations) and never generates persuasive or scam-style text, so the dual-use risk of the system itself being repurposed as a scam-writing tool is limited by what it is built to output, not by an added filter on top of a general-purpose generator. Second, the recall-first evaluation priority (Chapter~IV) is an ethical choice as much as a metric choice: in this threat model, a false negative leaves a user unprotected against a financial scam, while a false positive costs an unnecessary extra verification step, and the thresholds were set to weight the two outcomes accordingly rather than to maximize a single aggregate score.

Two limits on that design are stated plainly rather than left implicit. The training corpus is built from NCSC-published alert summaries and synthetic generation, not scraped from real victims' private messages, so no real user's phishing exposure is represented in the training data; this also means the corpus reflects reported and generated patterns rather than the full, unreported distribution of real scam traffic. And per the Limitations above, this prototype is not validated for unsupervised, safety-critical deployment; it is presented as an academic detection prototype, and a false sense of security from an unvalidated tool is a real risk the system's own output does not warn against beyond its stated confidence in each decision.

\section{Future Work}
The first priority is to train and select new checkpoints on the promoted train/validation data without touching the 220-row test split, then evaluate that held-out split once after checkpoint identities are frozen. A later real-world labelled test set should include difficult overlaps, especially Zalo or task-scam messages that mention banks and OTP codes. This would provide a more credible estimate of generalization and clarify the remaining subtype boundary.

The completed 100-row human sample reviews final dataset quality and records 87/100 human--judge agreement. A distinct second priority is independent human review of runtime-model explanation grounding and recommendation quality. That protocol should retain individual ratings so agreement can be reproduced.

The third priority is optional OCR preprocessing for screenshots. Screenshot-forwarded alerts are a common real-world variant alongside pasted text --- scam warnings and fake bank notices are frequently shared as images in Zalo and Messenger groups rather than typed directly --- so OCR coverage would extend the same threat surface this system already targets, not a new one. OCR output could feed the existing text contract without changing the QLoRA model or local privacy boundary, although the added component would require its own error analysis, since OCR misreads on Vietnamese diacritics could silently corrupt the downstream classification input.

The fourth priority is extending language coverage beyond Vietnamese. Chapter III's architecture rationale (Section~\ref{sec:qwen-vs-phobert}) already notes that \texttt{Qwen3-4B-Instruct-2507}'s multilingual pretraining base leaves room for this, unlike a Vietnamese-only encoder such as PhoBERT. The concrete next step is an English-language slang and scam-pattern seed set, collected the same way as the current Vietnamese corpus, so the existing QLoRA adapter could be retrained or extended to cover English-language scam text without a model change.
