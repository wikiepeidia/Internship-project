Vietnamese financial phishing increasingly appears through SMS and chat platforms such as Zalo, Messenger, Telegram, and Facebook \cite{groupib2022laser,ais2024biometricwarning}. In that setting, suspicious messages often contain sensitive banking details, phone numbers, one-time passwords, or account recovery prompts. This project studies a local-first pipeline for fine-tuning a local LLM to detect such threats without sending raw content to cloud services by default.

\section{Background and Motivation}
The term \textit{Localized} in the project title carries two meanings. First, the model runs entirely on-device --- local inference on consumer laptop hardware with no cloud API calls during analysis, preserving the privacy of the user's financial messages. Second, the LLM is adapted specifically to Vietnamese financial threat patterns through domain fine-tuning on a Vietnamese-language corpus, localizing its knowledge to the cultural and linguistic context of Vietnamese phishing. Both dimensions are required: privacy-preserving deployment alone would not address Vietnamese-specific scam patterns, and domain adaptation alone would not protect user data.

Three design constraints apply throughout: the pipeline is text-only, inference is offline or local by default, and detection prioritizes recall on high-harm scam classes. These choices narrow the scope compared to a full multimodal fraud assistant, but keep the system realistic for consumer hardware and well-suited for privacy-sensitive message analysis. They also address a practical safety question: how to reduce dangerous false negatives without relying on black-box predictions.

\section{Problem Statement}
\label{sec:problem-statement}
Two practical problems motivate this work. First, cloud-based fraud checking workflows require users to upload suspicious financial messages to remote services, creating avoidable privacy exposure. Second, the project requires explicit coverage of Vietnamese financial vocabulary, local social-engineering tactics, and mixed Vietnamese--English code-switching rather than assuming that a generic multilingual model already covers them. This project therefore targets a local fine-tuning pipeline that classifies suspicious text on-device and returns clear, grounded guidance instead of vague alerts.

Formally, the core learning problem is supervised multi-class text classification. The input is a single pasted message; the output is one primary label drawn from four mutually exclusive classes --- bank impersonation, Zalo social engineering, task scam, and benign --- together with a derived risk tier and evidence spans that support the assigned label. Every training example carries a ground-truth label for exactly this task, assigned during dataset construction (Section~\ref{sec:quality-check}) rather than added afterward. The explainability and recommendation outputs described later in this chapter are additional structured fields produced alongside the classification decision, not a replacement for it.

\section{Research Questions}
Based on the problem statement, this project addresses three questions:

\begin{enumerate}
\item \textbf{RQ1:} What four-class Vietnamese financial-threat performance do locally trained Qwen QLoRA and PhoBERT classifiers achieve under one shared, terminal evaluation protocol?

\item \textbf{RQ2:} Is parameter-efficient adaptation and local inference feasible on consumer laptop hardware, and what resource trade-off motivates QLoRA over ordinary LoRA on an 8~GiB laptop GPU?

\item \textbf{RQ3:} Can the detection pipeline return structured, evidence-grounded explanations --- risk tier, threat labels, suspicious cues drawn from the message text, and safe next-step recommendations --- rather than opaque confidence scores alone?
\end{enumerate}

\section{Project Contributions}
The work contributes more than a model checkpoint. First, it establishes a 2{,}097-row governed corpus whose train, validation, and terminal-evaluation partitions are separated by seed lineage rather than by individual paraphrase. Second, it documents and repairs a systematic synthetic-data failure: 240 retained Zalo messages used narrative scaffolding instead of direct-message language. Their controlled offline reconstruction preserved 60 semantic roots and produced five variants per root without external API calls or manufactured seed diversity. Third, it completes local Qwen QLoRA and PhoBERT training on the same corpus identities, retains raw training and validation evidence, and verifies a Q8\_0 GGUF export for the selected Qwen checkpoint. Fourth, it records one terminal two-model evaluation over the same 220-row cohort, including invalid-output and risky-to-benign safety counts. Finally, it separates maintained runtime, data, integrity, modeling, and evidence domains from historical experiment machinery so that the implementation can be explained and audited without attributing frozen metrics to rewritten source.

\section{Scope and Limitations}
The project is scoped as a text-only detection prototype for Vietnamese financial phishing. Image-based phishing (QR codes, forwarded screenshots), voice calls, deepfake audio, and malware analysis are out of scope. The implemented collection path targets retained alert pages from \url{https://tinnhiemmang.vn}; it does not implement ingestion of private user conversations. The resulting corpus remains synthetic-derived and is not a substitute for a real-traffic benchmark. The completed comparison uses one shared 220-row terminal cohort from the promoted corpus and cannot be reused for repair, retraining, threshold changes, or checkpoint reselection. Automated integrity regressions accessed the split files before the terminal model run; consequently, this report does not describe the partition as literally untouched. Those accesses did not display row content to a human, invoke either model, or influence the terminal result. The system is designed for single-message analysis, and multi-turn conversation tracking remains outside the current scope.

\section{Methodology Overview}
The project follows five connected stages. First, retained Vietnamese cybercrime-alert roots are expanded into a labelled development corpus and passed through schema/span validation, joined model-judge evidence, targeted human review, seed-lineage governance, and semantic convergence. The review of 324 flagged task-scam candidates produced 91 drops and 233 approved relabels, but only 57 relabels were admitted; 176 were excluded because they shared one non-independent lineage. A separate review replaced 240 retained narrator-framed Zalo records through controlled offline, model-assisted reconstruction from 60 preserved roots, generating five variants per root while keeping every variant within its original seed group. Second, bounded LoRA and QLoRA probes measure the hardware trade-off directly; ordinary LoRA is treated as resource-intensive, not as an OOM failure. Third, Qwen3-4B-Instruct-2507 is trained locally with genuine NF4 QLoRA while PhoBERT is trained locally as a full, non-quantized sequence classifier on the same train and validation identities. Fourth, the selected Qwen checkpoint is exported and independently load-smoked as a Q8\_0 GGUF artifact, while the text-only runtime preserves a stable structured-output contract. Fifth, both frozen models are evaluated exactly once on the same 220-row terminal cohort. The maintained architecture was subsequently reorganized for readability and provenance separation; this refactor did not produce or change the frozen metrics, and broader architecture hardening remains open.
