Vietnamese financial phishing increasingly appears through SMS and chat platforms such as Zalo, Messenger, Telegram, and Facebook \cite{groupib2022laser,ais2024biometricwarning}. In that setting, suspicious messages often contain sensitive banking details, phone numbers, one-time passwords, or account recovery prompts. This project studies a local-first pipeline for fine-tuning a local LLM to detect such threats without sending raw content to cloud services by default.

\section{Background and Motivation}
The term \textit{Localized} in the project title carries two meanings. First, the model runs entirely on-device --- local inference on consumer laptop hardware with no cloud API calls during analysis, preserving the privacy of the user's financial messages. Second, the LLM is adapted specifically to Vietnamese financial threat patterns through domain fine-tuning on a Vietnamese-language corpus, localizing its knowledge to the cultural and linguistic context of Vietnamese phishing. Both dimensions are required: privacy-preserving deployment alone would not address Vietnamese-specific scam patterns, and domain adaptation alone would not protect user data.

Three design constraints apply throughout: the pipeline is text-only, inference is offline or local by default, and detection prioritizes recall on high-harm scam classes. These choices narrow the scope compared to a full multimodal fraud assistant, but keep the system realistic for consumer hardware and well-suited for privacy-sensitive message analysis. They also address a practical safety question: how to reduce dangerous false negatives without relying on black-box predictions.

\section{Problem Statement}
Two practical problems motivate this work. First, cloud-based fraud checking workflows require users to upload suspicious financial messages to remote services, creating avoidable privacy exposure. Second, generic multilingual models do not reliably encode Vietnamese financial scam patterns, local social-engineering tactics, or mixed Vietnamese-English code-switching. This project therefore targets a local fine-tuning pipeline that classifies suspicious text on-device and returns clear, grounded guidance instead of vague alerts.

\section{Research Questions}
Based on the problem statement, this project addresses three questions:

\begin{enumerate}
\item \textbf{RQ1:} Can a 4-billion-parameter open-weight model, adapted with parameter-efficient fine-tuning (QLoRA) on a controlled-generation Vietnamese corpus, match or exceed the classification accuracy of the same base model used without adaptation on a four-class financial threat task?

\item \textbf{RQ2:} Is it feasible to deploy a fine-tuned LLM for Vietnamese phishing detection entirely on consumer laptop hardware (CPU-only, no GPU, no cloud API) while keeping single-message inference latency under 30 seconds?

\item \textbf{RQ3:} Can the detection pipeline return structured, evidence-grounded explanations --- risk tier, threat labels, suspicious cues drawn from the message text, and safe next-step recommendations --- rather than opaque confidence scores alone?
\end{enumerate}

\section{Scope and Limitations}
The project is scoped as a text-only detection prototype for Vietnamese financial phishing. Image-based phishing (QR codes, forwarded screenshots), voice calls, deepfake audio, and malware analysis are out of scope. The training corpus is built through controlled generation from real NCSC seed cases; no real user messages are used. Evaluation is performed on a 254-example internal holdout, not on a production benchmark with real traffic. The system is designed for single-message analysis; multi-turn conversation tracking is left for future work.

\section{Methodology Overview}
The project follows a four-stage pipeline. First, a labelled dataset is constructed by collecting real phishing seed cases from the Vietnamese NCSC portal (\textit{tinnhiemmang.vn}) and expanding them into a 3{,}000-row corpus using the \texttt{claude-3-5-haiku} API, with Pydantic schema validation and a manual quality-judge pass at the generation boundary. Second, a text-only local runtime accepts a suspicious message and dispatches it to a configured model backend. Third, the open-weight \texttt{Qwen3-4B-Instruct-2507} model is adapted using QLoRA ($r{=}16$, $\alpha{=}32$, NF4 4-bit) and the merged adapter is exported as a GGUF Q8\_0 artifact for CPU inference via \texttt{llama.cpp}. Fourth, a structured decision layer wraps the model output to return a risk tier, threat labels, grounded suspicious cues, and safe next-step recommendations. The full pipeline is evaluated on a 254-example seed-disjoint holdout, comparing the fine-tuned model against the base model without adaptation.
