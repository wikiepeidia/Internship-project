The layout of the source tree and what each folder does is described in Chapter~IV. One point bears repeating: \texttt{src/model\_adaptation} holds the older experiment code. It is kept because the recorded results were produced with it, and it should not be read as the current design.

Neither trained model is stored in the repository: the exported Qwen file is 4.28~GB, and PhoBERT's weights and optimizer state together are close to 1.6~GB. Both are too large for git. The Qwen export's checkpoint origin and file size are noted alongside it, and it was loaded twice to confirm that it works.

\section*{Appendix 4: What Went Wrong}
\addcontentsline{toc}{section}{Appendix 4: What Went Wrong}

Several things went wrong during this project, and none of them were left out of the record. Table~\ref{tab:failure-recovery-ledger} lists the main ones and what was done about each.

\small
\begin{longtable}{p{2.8cm}p{6.1cm}p{5.1cm}}
\caption{What went wrong, and what was done about it.}\label{tab:failure-recovery-ledger}\\
\toprule
\textbf{Stage} & \textbf{What went wrong} & \textbf{What was done about it} \\
\midrule
\endfirsthead
\toprule
\textbf{Stage} & \textbf{What went wrong} & \textbf{What was done about it} \\
\midrule
\endhead
Rebuilding the Zalo messages & One whole group of Zalo messages, 240 of them, had been written as narration describing a scam instead of as a scam message. & They were rewritten from the same source articles, producing 300 replacements, four of which were rejected for drifting away from their source. The final set keeps 296. They are still generated messages, and they were written by the same model family as the judge that later scored them. \\
\addlinespace
Ordinary LoRA measurement & The first attempt stopped before the first step because a strict check expected an older library version. The corrected retry ran 31 steps and then ended on a driver fault. & No out-of-memory error occurred, but memory reached 7{,}902 of 8{,}151~MiB with only 9~MiB free, and the run pointed at roughly eighteen hours of computation. This is evidence about the hardware only; it does not prove that LoRA is impossible. \\
\addlinespace
QLoRA measurement & The projection this run produced counted only one validation pass, not the 219-message generation the full run repeats at every checkpoint, so it understated the real duration. & The measurement adapter was deleted and the full model was trained from a fresh start. The projection shows that the method fits the card; it is not an observed run time. \\
\addlinespace
Full Qwen training & The first full attempt reached real checkpoints but had two defects: the output folder name left out the run ID, and one code path rebuilt the saved file through the wrong Python type. & The run was stopped on purpose. A clean run restarted from step zero, completed 1{,}245 steps, selected step 200, and produced the exported model. \\
\addlinespace
Full PhoBERT training & PhoBERT had to stay an ordinary four-class classifier with nothing quantized. & The accepted run completed 312 steps and selected step 100. No PhoBERT GGUF was made. \\
\addlinespace
Starting the final evaluation & Five attempts to launch the final evaluation stopped themselves before reading anything, on their own access checks. & The sixth attempt worked: it read the 220 held-out messages once, evaluated both models, and then locked itself against being run again. The result stands on that one run. \\
\bottomrule
\end{longtable}
\normalsize

An earlier draft of this report said the held-out messages had been left untouched until the evaluation. That was wrong. Automatic file checks had opened them, before and after the run, to confirm nothing had been corrupted; those checks never showed a message to a person and never ran either model. The correct way to put it is that the models saw those messages exactly once, not that nothing had ever read the files, and this report says it that way now.

The code was also reorganised to be easier to read, but a later review still found six critical and three warning findings. That work made the project easier to navigate; it did not make it secure, and it is not what produced the results in this report.
